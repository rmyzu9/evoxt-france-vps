## **一、Evoxt法国机房到底是个什么定位**

先说清楚一个事情：Evoxt的法国机房在巴黎，属于它官网Pricing页面里列的"Standard"标准网络层，不是Premium也不是Premium Plus。这意味着什么？意味着它的网络是走常规国际线路，不是CN2 GIA那种专门优化回国的优质线路。

但"标准"不等于"差"。Evoxt官方对巴黎机房的描述是：

> Connected to France-IX, and multiple Tier 1 ISPs, providing low latency to the France and Europe.

翻译过来就是接入了France-IX巴黎互联交换点，同时对接多家Tier 1一级运营商，对法国本土和整个欧洲的延迟都很低。这个定位其实很清楚——它适合做欧洲业务、跑欧洲用户访问的服务，或者作为欧洲中转节点。

至于国内访问，从实测数据看，平均延迟大概在197ms左右，走的是主流国际带宽。电信走163骨干直连巴黎节点再转telia；联通走AS4837到法兰克福再转telia；移动走CMI到伦敦再转cogentco。回程基本都走arelion网络到法兰克福或伦敦，再对接三网骨干回国。说人话就是：三网都有相对稳定的回程路径，不是绕地球半圈那种，但也不是直连CN2那种丝滑体验。

## **二、硬件性能：AMD高频U+NVMe，跑分确实能打**

Evoxt全机房统一用AMD系列CPU，主频官方标称3.5GHz+，突发最高能到6.0GHz。法国机房也不例外，纯NVMe SSD阵列，KVM虚拟化，1Gbps共享端口。

我实测的VM-0.5是最低配，1核512MB，CPU主频读出来是4491MHz，硬盘I/O大概2.1GB/s。这个I/O成绩放在同价位里属于第一梯队，很多大厂的入门款NVMe也就这个水平甚至更低。

UnixBench跑分方面，2核1线程大概3935分。这个分数什么概念？跑个轻量级网站、做个小爬虫、挂个Telegram bot、跑个监控脚本，完全够用。你要是拿它去跑数据库重负载或者视频转码，那确实是难为它了，但那本来也不是这个价位该干的事。

CPU单核性能是Evoxt一直以来的卖点。官网首页还专门放了个对比图，把自己的6.0GHz和AWS的2.4GHz、Azure的2.3GHz、DigitalOcean的2.3GHz、GCP的2.2GHz放一起比。数据是2020年采集的，现在各家肯定都有更新，但Evoxt在单核频率上确实一直舍得堆。

## **三、网络实测：三网路由、延迟、流媒体解锁**

这部分是大家最关心的，也是我花时间最多的。

### **国内三网延迟**

平均197ms，电信、联通、移动都在190-200ms这个区间。这个延迟对欧洲机房来说算正常水平，比德国法兰克福略低一点，比英国伦敦略高一点。如果你做过欧洲节点的对比，应该知道这个数据在欧洲机房里属于中规中矩。

### **三网去程路由**

- **电信**：上海出口 → 163骨干直连法国巴黎节点 → telia线路进机房
- **联通**：AS4837直连德国法兰克福 → telia转巴黎
- **移动**：CMI直连英国伦敦 → cogentco转巴黎

### **三网回程路由**

- **电信**：机房 → arelion到伦敦 → 电信骨干回国
- **联通**：机房 → arelion到法兰克福 → 联通AS4837回国
- **移动**：机房 → arelion到法兰克福 → 移动CMI回国

可以看出回程都走了arelion（就是以前的Telia）这家Tier 1运营商，在法兰克福或伦敦对接三网骨干。这种走法的好处是回程路径相对稳定，坏处是毕竟多了一跳，延迟会比纯直连高一些。

### **流媒体解锁**

IP归属法国，属于原生欧洲IP。实测能解锁部分跨区域流媒体，具体能解锁哪些平台会随IP段和时段波动，这里就不写死数据了，免得误导。但法国原生IP对欧洲本地流媒体（比如Canal+、TF1这些）的解锁是没问题的，跑TikTok欧洲区做中转也是很多人买这个机房的原因之一。

### **带宽实测**

1Gbps共享端口，国内部分地区下载能跑到几百Mbps，亚洲节点上行下行也都不错。Speedtest全球节点测试，欧美节点基本能跑满。iperf3测欧美节点带宽也稳定。日常建站、跑代理、做中转，带宽是够用的。
